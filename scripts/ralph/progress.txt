## Codebase Patterns
- Backend uses SQLAlchemy ORM plus create_all; new JSON columns need defaults for backward compatibility.
- Frontend uses Next.js App Router and frontend/lib/api.ts as the single API access layer.
- /students/me is the source of truth for the current target job, and writes go through /students/me/target-job.
- Path results, history replay, and report pages must share one graph structure instead of building separate view models.
- Report generation must check evidence sufficiency first and return insufficient_data when resume evidence is missing.
- Progress UI state must follow real task state instead of static completed markers.
- OCR failures must distinguish parse errors, service errors, and network or timeout errors.
- PathRecommendation model is the DB backing for career path snapshots; add new JSON columns with `default=dict` for backward compat.
- get_path_result endpoint must provide backward-compatible fallback when graph snapshots are missing from old records.
- CareerPathService.plan_path returns vertical_graph and transition_graph; both must be persisted to PathRecommendation.
