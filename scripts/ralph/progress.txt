## Codebase Patterns
- FastAPI 查询参数名不能与 Python 内置名称（type、id、list 等）冲突，用 `Query(alias=...)` 解决
- 后端使用 FastAPI + SQLAlchemy 2.0（Mapped/mapped_column 声明式）+ SQLite/PostgreSQL
- 所有 API 路由在 `/api/v1/` 前缀下，各资源有独立 router 文件（`backend/app/api/routers/`）
- 依赖注入通过 `ServiceContainer` 数据类（`backend/app/services/bootstrap.py`），用 `Depends(get_container)` 获取
- 认证使用 JWT Bearer token，`get_current_user` 依赖验证（`backend/app/api/deps.py`）
- 测试使用 `pytest` + `FastAPI TestClient`，配置在 `backend/tests/conftest.py`，mock providers 通过环境变量切换
- 前端使用 Next.js 15 App Router，API 客户端在 `frontend/lib/api.ts`，类型内联定义
- 数据库无迁移系统，启动时 `Base.metadata.create_all()` 自动建表
- Provider 模式：LLM/OCR/Storage/Graph/RAG 均有 mock 和 real 实现，通过 `.env` 切换
- 无 Alembic 迁移，表结构变更需手动处理或重建数据库
- 测试中上传文件需要用 `python-docx` 生成有效 DOCX，不能用纯文本伪装 PDF
- `Resume.file_id` 是 unique FK，天然支持多简历隔离，每份简历独立存储 `parsed_json`
- OCR 解析结果双写：`UploadedFile.meta_json["ocr"]`（完整）和 `Resume.parsed_json`（仅 structured_json）
- `AnalysisRun` 模型是分析上下文的枢纽，通过 FK 绑定 profile_version、match_result、path_recommendation、report
- 分析路由 `PATCH /{run_id}/context` 用于逐步关联下游结果，`exclude_unset=True` 保证部分更新不清空其他字段
- `ProfileVersion.snapshot_json` 存储完整画像快照，包含 `uploaded_file_ids` 和 `mode` 用于追溯来源
- Router 层通过 `try/except ValueError` 捕获 service 层业务校验并返回 400 错误
- 前端学生画像页面在 `frontend/app/student/profile/page.tsx`，已集成版本历史列表和快照查看
- `resolve_target_job()` 在 `students.py` 中有 4 级优先级回退：手动确认 > career_goal 映射 > 最近匹配 > 空值
- `ensure_demo_users()` 启动时创建 user_id=1（student_demo），测试中 dev-bypass 直接映射到该用户
- 匹配、路径规划、报告路由均支持空 job_code 回退到已确认目标岗位
- `CareerReport` 模型有 `profile_version_id`、`match_result_id`、`analysis_run_id` 上下文绑定字段，与 MatchResult/PathRecommendation 模式一致
- 报告 `generate_report()` 接受 `analysis_run_id` 并自动从 run 回填 `profile_version_id` 和 `match_result_id`
- `AnalysisRun.report_id` 会在报告生成时自动回写，形成双向绑定
- SQLAlchemy JSON 列原地修改 dict 不会触发 dirty tracking，需要 `obj.json_col = new_dict` 整体替换才能 commit
- `ReportVersion` 是报告变更的审计记录，save/polish 都应创建版本记录保持追溯能力
- `GET /students/me/history` 聚合 7 种记录类型（upload/profile/matching/path/report/chat/feedback），支持 `?type=` 过滤
- `HistoryTitle` 表存储用户自定义标题，key 为 `record_type-ref_id`，rename 端点 upsert
- `FollowupRecord` 模型存储教师反馈（record_type: advice/comment/followup），目前无独立前端展示页
- pytest 共享数据库测试中，种子数据测试必须通过 username 模式过滤只查自己创建的数据，避免其他测试 fixture 副作用
- 登录 API `/auth/login` 返回 `LoginResponse`（非 APIResponse 包装），token 直接在 `resp.json()["access_token"]`
- Windows 下 SQLite 测试 DB 使用 `uuid.uuid4().hex[:8]` 生成唯一路径，避免并发进程文件锁冲突
- conftest.py 通过 `import app.db.session as _db_mod; _db_mod.engine = ...` monkey-patch 全局 engine，确保 TestClient lifespan 使用测试 DB
- `seed_demo_students()` 在 `bootstrap.py::initialize_demo_data()` 中调用，创建 35 名模拟学生（User+Student+Profile+Match+Report+Task）
- 种子数据通过检查 `demo_student_001` 用户是否存在实现幂等，`JobProfile` 缺失时自动创建占位记录
